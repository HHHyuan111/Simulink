# 测速反馈

第十五项固定实验`speed_feedback`：从“观察计数测速”推进到“让计数测速进入原速度PI”。固定对照为原速度、窗口测速、长窗测速三组。角度仍走原路径，速度滤波关闭，PI数值与电机、负载、母线、初态和真实事件时序保持一致。

## 操作

```matlab
cd('D:/simulink/modern'); addpath('teaching')
open_pmsm_experiments
```

选择“测速反馈”，恢复固定参考，再运行三组。三个输入与上一项相同：每机械转解码计数10000、窗口2拍、长窗8拍。计数范围20—1000000，窗口2—7拍，长窗大于窗口且最大32拍，全部为整数。短窗1拍仍在后台记录。每组默认50ms，可设50—100ms；这是短时启动对照，不预设稳态。

```matlab
r=run_pmsm_experiment('speed_feedback');
r=run_pmsm_experiment('speed_feedback',[5000 3 12],.05);
% 100ms参数回归工况，用来继续观察限幅退出后的响应：
r=run_pmsm_experiment('speed_feedback',[5000 3 12],.1);
[again,check]=repeat_pmsm_experiment(r.folder);
```

“展开反馈选择”打开原模型新增的`速度反馈`；计数差分仍在`角度设置/编码器/测速`，可继续向内读。测速块自身负责生成候选及记录，真正的反馈连接由外部`速度反馈`模块完成。展开默认显示窗口测速开启，仅用于阅读；固定运行使用界面与计划中的三组参数。恢复参考或运行结束会移除临时模块并恢复原连接，不保存覆盖主SLX，也不新建一套控制器。

## 连接怎么变

原来：机械真实速度 → 原速度任务保持 → 速度误差 → 原速度PI → 转矩/iq给定。

现在：机械真实速度和计数差分候选 → 反馈选择 → 原速度任务保持 → 原速度PI。

只在原保持块入口插入选择，原保持块及其到速度误差的连接保留。计数读取与滚动测速20kHz，读取偏移28.875µs；速度PI10kHz，执行偏移78.875µs，每两次读取取一次当拍候选。选用2拍不意味着测速只更新10kHz；候选每拍滚动更新，原速度任务才每两拍消费一次。

反馈选择内部先选择短窗、窗口或长窗的完整测速包，再看有效标志。有效时使用其机械rpm，无效时使用0；最后由“计数测速反馈”开关选择这个值或原速度。未增加滤波和额外一拍延迟。窗口平均本身的动态误差仍存在，不能把它算成又插入一个纯延迟块。

| 组别 | 反馈开关 | 实际来源 |
| --- | --- | --- |
| 原速度 | 关 | 原机械速度，经过原速度任务保持 |
| 窗口测速 | 开 | 指定窗口的计数差分，默认2拍 |
| 长窗测速 | 开 | 长窗口的计数差分，默认8拍 |

三组分别运行闭环，后两组改变反馈后，电流、转矩、真实转速及计数轨迹都允许随之改变。与上一项“一次仿真三观察器共享轨迹”不同，不能把三组的测速差都解释成同一物理轨迹上的窗口差异。每组仍记录全部三种候选，以独立核对其计数来源。

## 启动、有效性与边界

仍要求W+1个读取端点。历史不足时零初值、标记无效，不用真实速度回填；默认2拍候选在第一个速度任务样本无效，8拍候选在前四个速度任务样本无效。原速度组虽然记录这些候选无效标志，实际原速度反馈仍可用。

本轮有效标志只作来源选择和观测，尚未建立完整启动门控、故障停机或有效样本丢失后的安全策略。后续接启动状态机时，需要明确何时允许速度PI、如何初始化积分和如何接管。当前选择开关用于运行前配置，不宣称支持任意时刻无扰热切换。

速度单位是机械rpm，不乘极对数。差分公式、正反转与单圈解绕沿用[计数测速](README_计数测速.md)。窗口内机械位移应小于半圈；分析器用真值检查适用域，估计器不靠真值消除混叠。8拍及更长是Simulink历史延迟支持的教学扩展，不能直接套用原固件8槽历史数组；固件的ready初值和后续200Hz速度低通也没有被宣称为完全复刻。

## 三页报告怎么读

- 测速反馈：上排看真实速度与实际进入PI的速度，下排看相应iq给定。
- 闭环响应：看各自的真实速度、iq给定、转矩和真实q轴电流。
- 反馈来源：看启动时实际输入、候选有效性、反馈误差和来源开关。

逐列反馈页用于辨认每组信号来源，纵轴按各组数据自动取范围；跨组比较波动幅度应看叠加的闭环响应页，其三组共用同一坐标。

先看“速度反馈有没有阶梯”，再看“PI有没有把阶梯传到iq给定”，最后看“真实电流和转矩有没有响应”。此次默认50ms加速期间三组iq给定都达到8A限幅，测速阶梯已进入PI，但给定被限幅遮住，物理响应几乎相同。不能因速度曲线接近就判断来源开关没生效，也不能因反馈更平滑就判断闭环一定更好。另用[5000,3,12]、100ms工况继续观察限幅退出后的行为，三组仍共用相同参数；默认与参数工况同时改变计数、窗口及长度，不能把两种工况之间的指标差归因于单一因素。指标按实际波形记录，不计算或宣称THD。

## 记录与验证

每组保留32路原始时间序列，三组共96路。`log_speed_control`直接取原速度保持输出，也是原速度误差块实际输入；新增`log_speed_feedback`在同一速度任务时刻记录8列：选用候选rpm、候选有效标志、反馈开关、窗口选择编号、原速度、选择输出、候选当前读取时间、候选历史来源时间。

默认50ms工况的96路Time/Data已独立严格复现。末20ms实际反馈误差RMS约0/25.14/10.19rpm，三组iq给定均为8A，末端真实转速均约2006.84rpm；这是限幅中的启动结果，不能据此宣称2拍或8拍闭环优劣。

100ms参数工况[5000计数,3拍,12拍]在末20ms记录到以下结果。这里已经退出8A限幅，计数阶梯能向电流给定及转矩传递；仍是有限时间窗，转矩标准差同时包含动态趋势和波动，不等于纯谐波幅值。

| 反馈 | 实际反馈误差RMS | iq给定逐拍变化RMS | 转矩标准差 |
| --- | ---: | ---: | ---: |
| 原速度 | 0rpm | 0.00640A | 0.01151N·m |
| 3拍测速 | 33.81rpm | 0.58882A | 0.01887N·m |
| 12拍测速 | 9.30rpm | 0.13880A | 0.01220N·m |

“iq给定逐拍变化”是相邻控制日志记录差的RMS，日志20kHz、速度命令10kHz保持，包含保持拍的零差；它不是iq误差RMS。默认与扩展工况单独存档，扩展叠加响应页在统一图库中另存`extended_response.png`，参数与来源记在`summary.json`的`extended`字段，不覆盖默认实验图。

`feedback_samples.csv`逐次保存实际PI输入、候选来源与误差；无历史来源编号为0、时间为NaN。原始MAT仍保留有限零初值及标志。`feedback.json`记录每组来源核对、三个候选的量化/窗口误差、实际反馈误差、iq给定逐拍变化、转矩标准差和末端速度。

验收入口`validate_pmsm_speed_feedback`分为`default/repeat/parameters/finish`，最终报告为`experiment_speed_feedback_validation.json`。检查选择器三个窗口、关闭旁路、正负候选、无效零值、原保持执行时刻、实际计数公式与PI输入来源、参数回归、GUI展开/恢复及文件篡改拒绝。原速度组与上一项31路比较，另独立复跑默认96路及100ms参数工况96路，并重跑上一项观测场景检查兼容性。100ms原速度组只核对其前50ms的21路完整观测与默认参考原始点，不拿不同尾部记录密度的诊断数组作完整时间轴比较。主模型、固定参考、PI与布局保持；图库重绘与仿真复跑是两种证据。

以上专项验收全部通过。默认旁路与上一项31路Time/Data严格相同，独立重跑旧观测场景31路也严格相同。统一图库15个场景、45张PNG的来源与图片指纹检查通过；本场景[默认反馈](experiments/examples/speed_feedback/comparison.png)、[默认响应](experiments/examples/speed_feedback/response.png)、[反馈来源](experiments/examples/speed_feedback/mechanism.png)及[100ms扩展响应](experiments/examples/speed_feedback/extended_response.png)分别保留，不把图库重绘视作全部场景重新仿真。

下一步建议单独增加速度滤波对照：同一计数窗口下比较“无滤波 / 固定截止频率滤波”，继续记录滤波前后和实际PI输入。先核对固件递推与更新时刻，200Hz仅作源码配置参考，不标为实测整定值。反馈来源与窗口先固定，让平滑收益及动态滞后能够分别解释。之后再做启动对齐与接管、状态保护、固件控制律及实测校准。

上述受控滤波对照已在后续第十六项[速度滤波](README_速度滤波.md)实现并验收；本页第十五项的三组仍保留无速度滤波的原定义。
