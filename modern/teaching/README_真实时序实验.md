# 真实时序实验

本轮把已有真实事件模型接入固定实验入口，建立可重复的周期时间线。沿用原电机、3000rpm、24V、0.207N·m负载、零初态和PI；不增加控制算法、采样重构、窗口失效策略或主动保护。主模型与第一版固定参考保持。

两组分别为“简化模式”和“事件模式”，共同设置计算耗时，只有事件模式使用它。后者开启`时序设置.real_on`，低侧窗口、旧整拍采样/输出延迟、死区及其他附加因素关闭。

这不是纯延迟性能对照：模式切换还包括1μs→62.5ns步长、载波方向、C/B/A顺序采样、任务相位、CCR量化和预装载更新。运行状态图仅为上下文，不据此把全部波形差归因于计算耗时或宣称性能改善。

## 操作

```matlab
cd('D:/simulink/modern')
addpath('teaching')
open_pmsm_experiments
```

选择第十项“真实时序”，恢复完整固定参考后运行。窗口的“计算耗时”默认5μs，按0.0625μs步进，允许0.0625—20μs；默认两组各运行50ms。允许范围是当前事件配置下的教学范围，不保证所有参数组合性能良好。现有模型要求整组采样及计算在一个PWM周期内完成。

```matlab
pmsm_reference('restore')
r=run_pmsm_experiment('timing_events',5);
pmsm_experiment_verify(r.folder);
[again,v]=repeat_pmsm_experiment(r.folder);
```

计算耗时改变后，旧报告按钮失效，需要重新运行。每次创建独立结果目录，结束恢复参考，不保存覆盖主SLX。与上一轮相同，从已保存原始MAT启动独立进程分析出图，避免在保留仿真原生状态的会话里新增图形分析；这不代表已定位本机MATLAB原生崩溃根因。

## 三页报告

“控制时序”：显示末端两个PWM周期的中心对齐计数、ADC事件、控制与PWM事件、已写入/已生效的指令序号。一网格脉冲用事件点显示，没有人为拉宽。图片只保留主题、必要标识和单位；绝对时间窗口与解释在配套文字中。

“采样电流”：只显示事件模式，叠加每相物理电流和JEOS发布的采样保持值，并比较物理三相电流和与顺序样本之和。每相样本需要分别核对其实际孔径结束时刻，不能拿同一时刻的三个真值代替三个顺序采样值。

“运行状态”：显示两组50ms启动局部的转速、真实dq与转矩，分别使用各自记录时间轴，不平移或补点对齐。短时启动记录不代表严格稳态或完整启动性能验收。

## 沿着默认时间线读

下表以中心对齐计数谷底为周期0。数值是当前模型参数对应的事件，不是已经在开发板上测得的时间。

| 事件 | 周期内时间 / μs | 含义 |
| --- | ---: | --- |
| ADC触发 | 24.375 | 固件源码推导的相位假设，待实测；附加等待当前为0 |
| C相孔径结束 | 25.5625 | 保存C相电流 |
| B相孔径结束 | 27.0625 | 保存B相电流 |
| A相孔径结束 | 28.5625 | 保存A相电流 |
| JEOS / 电流任务 | 28.875 | 整组三相交付，执行快环 |
| CCR写入 | 33.875 | JEOS后5μs；5μs是演示计算耗时 |
| 下一UEV / 新CCR生效 | 50 | 预装载值进入活动输出 |

因此默认计算耗时5μs，写入后等待16.125μs，JEOS到生效共21.125μs。不能把这三个数作为三个独立延迟重复叠加。UEV每25μs有一次机会，不意味着每25μs一定有新指令生效；写入序号与生效序号帮助检查是哪一条指令生效。

事件图起点的CCR生效可能来自上一周期已经写入的指令，不能只按当前窗口内的左右顺序理解因果；用序号和`timing.json`中的配对记录追溯。

当前快环周期50μs、首拍偏移28.875μs，速度任务周期100μs、首拍偏移78.875μs。控制执行周期、相位和日志记录周期分别检查，不从普通曲线的阶梯宽度反推全部调度。事件网格62.5ns是数值设置，不表示逐个复刻160MHz定时器时钟沿或CPU指令。

转速波形在本场景按快环时刻记录，并不表示速度PI也按20kHz执行；实际速度任务周期仍为100μs。两模式日志相位及网格不同，也会影响短窗口中可见的PWM纹波，不能把事件模式曲线较平滑直接称为控制改善。

顺序样本即使没有噪声、零偏，三相之和也可能不为零，因为来自不同时间。当前低侧窗口关闭，诊断仍记录有效标志，但没有按标志屏蔽或保持样本；这些图不能视为低侧采样失效策略已通过验收。

## 原始记录与核对

每组保留24路：原21路，加`obs_adc_timing`、`obs_pwm_timing`、`log_Tcm_applied`。ADC/PWM事件保留尾部4000点；物理电流和实际生效调制阈值按各自求解网格记录，保留尾部8000点。事件模式分别覆盖末250μs和末500μs，简化模式分别覆盖末4ms和末8ms；高频日志不是完整启动档案。普通控制记录保留全程。

`events.csv`保存事件名称、绝对时间、周期编号和周期内相位。`timing.json`保存任务周期/相位、窗口、每条指令JEOS/写入/生效配对，以及采样和实际输出的核对误差。

分析直接按事件网格查找各相孔径结束时的原始电流，不插值、不按峰值平移。写入和生效通过指令序号配对，并用实际输出阈值核对生效事件；不把诊断标志本身当成唯一依据。

验收入口`validate_pmsm_timing_events`分为默认窗口运行、48路整套复跑、编译周期/参数生效、旧实验回归四个独立进程。正式报告为`experiment_timing_events_validation.json`，全部通过后发布。验收包括已有事件、各相物理采样值、实际输出、简化模式历史参考、窗口操作、矛盾延迟拒绝、事件文件改动检测与主模型/完整参考/PI/布局保持。

2026-10-13 MATLAB R2026a Update 5验收全部通过：两组24路、共48路Time/Data逐点复现；末端5条指令完整配对，各相孔径结束真值与发布样本最大误差为0，实际生效阈值与配对记录最大误差为0。编译后的电流PI/SVPWM为50μs周期、28.875μs偏移，速度PI为100μs周期、78.875μs偏移。8类无效输入、旧整拍延迟冲突、窗口运行/报告/参数改动失效清除和事件CSV改动检测均通过，主模型、完整参考、PI、布局保持。

简化模式与历史16路记录的数值逐点相同。物理电流日志因采样时间表达式从`T`改为`timing_h`而有约6.94×10⁻¹⁸s的浮点时标末位差异；仅该路按同一1μs网格对应原始样本并限制时标误差，未插值或改数据。旧电流零偏实验两组各21路仍通过严格Time/Data逐点回归。历史兼容核对与新实验48路严格复现是两种不同检查。

## 计算耗时参数验证

以下两次运行保持默认触发与更新模式，实际输出阈值逐点相同；这里只核对参数生效，没有开展跨更新边界优化。

| 计算耗时 / μs | 写入时刻 / μs | 生效边界 / μs | JEOS至生效 / μs |
| ---: | ---: | ---: | ---: |
| 5 | 33.875 | 50 | 21.125 |
| 10 | 38.875 | 50 | 21.125 |

计算更慢会挤占写入裕量，但只要仍赶上同一边界，生效时刻可以不变。这是本轮直接验证出的现象，不用额外增加一拍延迟来制造差异。

## 整体框架与下一步

固定基线与开关 → 功率级与测量链对照 → **已有真实时序事件观测** → 同架构计算耗时/更新边界对照 → 位置反馈、启动与保护 → 固件核心和实测校准 → 组合工况验收。

下一步建议先沿本轮事件图带读一遍，再在共同的真实时序架构下研究“写入赶上或错过更新边界”。共同触发相位、更新模式和网格要先固定，只改变计算耗时；若采用教学相位，应与当前未实测的固件相位假设分开标明。不要直接用简化/事件模式切换替代该单参数实验。
