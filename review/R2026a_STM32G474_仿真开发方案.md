整理日期：2026-10-10（北京时间）。

已确认：MATLAB R2026a，MCU 为 STM32G474RET6，只使用 PMSM。待补充：实际开发板和功率板、电机参数、采样电路、位置反馈方式、固件工程与 `.ioc`。

本文最初是后续开发设计与资料整理。后续已针对本机只有 MATLAB/Simulink 的安装环境建立可运行的信号方程替换版，见 `D:\simulink\modern\README_运行与替换说明.md`。没有编译固件或连接开发板；文中频率和目录草案不是已经验证的板级配置。

## 1. 建议的开发目标

目标应是：让同一套控制算法，在仿真和开发板上接收相同定义的采样量，按相同节拍执行，产生相同定义的 PWM 命令；再用真实数据校准电机、功率级和测量链路。

整个闭环应包含下面这些部分：

```text
指令、启停、故障状态
          ↓
固件控制逻辑 → CCR/占空比 → 定时器、更新事件、死区 → 逆变器 → 电机及负载
     ↑                                                            ↓
输入换算、校准 ← ADC 数字结果/位置计数 ← 采样时刻、模拟滤波、传感器模型
```

电机真实电流、真实角度只用于检查与基准对照。接入实际传感器/观测器后，控制器通过相应反馈接口获取它们。

用户已确认只使用 PMSM，后续模型阅读、迁移和板级开发均围绕仓库 PMSM 主模型展开。

## 2. 官方资料已经确认的条件

### 2.1 R2026a 的迁移方向

Specialized Power Systems 已在 R2026a 移除。仓库里的 `powergui`、`powerlib`、`sps...Lib` 需要迁移到原生 Simscape Electrical。[官方迁移说明](https://www.mathworks.com/help/simscape-electrical/ug/upgrade-sps-models-to-use-simscape-blocks.html)

R2026a 提供 `spsConversionAssistant`：它生成一个追加 `_simscape` 名称的模型和 HTML 报告，报告区分完全支持、部分支持及不支持的块。转换后仍需人工检查；函数返回的可写状态也不代表仿真已经通过。[R2026a 转换函数文档](https://www.mathworks.com/help/releases/R2026a/sps/ref/spsconversionassistant.html)

### 2.2 STM32G474 可以使用的官方入口

R2026a 引入 STM32 Microcontroller Blockset，提供 STM32 外设建模和部署工作流。官方 R2026a 的 ST 硬件示例清单中包括 NUCLEO-G474RE 的开环控制、无感 PMSM FOC 和参数辨识参考。[产品要求](https://www.mathworks.com/support/requirements/stm32-microcontroller-blockset.html)、[R2026a ST 示例清单](https://www.mathworks.com/help/releases/R2026a/mcb/gs/examples-supporting-stm-hardware.html)

NUCLEO-G474RE 示例可参考外设调度和工程组织；你的 STM32G474RET6 开发板仍需按实际 PCB、电流采样和引脚重新配置。相同 MCU 型号不能保证整个参考板工程可直接运行。

G474RE 有单精度 FPU、最高 170 MHz 主频和适合电机控制的模拟及定时器资源。仿真中的控制数据类型应对齐实际固件：如果固件使用 `float`，先使用 `single`；如果固件使用定点或混合运算，则复现对应的定标、舍入和饱和规则。[ST 产品资料](https://www.st.com/en/microcontrollers-microprocessors/stm32g474re.html)

### 4.2 电气与信号块的重建映射

| 仓库中的部分 | R2026a 的重建方式 | 重点核对 |
| --- | --- | --- |
| Permanent Magnet Synchronous Machine | 原生 `PMSM` | 绕组接法、相电阻、Ld/Lq、磁链、极对数、角度定义、机械惯量 |
| Universal Bridge | `Converter (Three-Phase)`，必要时用离散桥臂搭建 | MOSFET/IGBT 类型、六路门极顺序与电平、二极管、导通压降 |
| DC Voltage Source | 原生直流源，逐步增加母线电容、ESR、供电阻抗 | 真实 Vdc 与母线动态 |
| Three-Phase V-I Measurement | 原生电流、电压传感器与 PS-Simulink 接口 | 电流正方向、线电压/相电压和单位 |
| 机械转速、角度、负载接口 | 原生机械测量、转矩源和机械参考 | 正转方向，电机与负载惯量避免重复计入 |
| powergui | 为物理网络配置 Solver Configuration、Electrical Reference 等 | 没有一个与 powergui 功能完全相同的替换块 |
| 旧 powerlib 坐标变换 | 普通 Simulink/MATLAB Function 或 Motor Control Blockset 算法 | Clarke 缩放、Park 符号、d/q 零角基准 |

块依据：[R2026a PMSM](https://www.mathworks.com/help/releases/R2026a/sps/ref/pmsm.html)、[R2026a Converter (Three-Phase)](https://www.mathworks.com/help/releases/R2026a/sps/ref/converterthreephase.html)、[原生三相建模示例](https://www.mathworks.com/help/releases/R2026a/sps/ug/build-and-simulate-composite-and-expanded-three-phase-models.html)。

转换时特别注意：原生 Converter 的门极接口不能靠复制原来的六元素排列来保证正确；应按上/下桥臂和 A/B/C 相的名称逐一映射。选择 MOSFET 模型后，门极阈值也必须与门极驱动信号的物理电平匹配。

R2026a 原生 PMSM 可以直接按 Ld、Lq、磁链参数化。其角度定义和 Park 约定必须与固件一致；反电动势常数、转矩常数也要先统一相/线、RMS/峰值和转速单位，不能直接填入同名字段。[PMSM 参数与坐标定义](https://www.mathworks.com/help/releases/R2026a/sps/ref/pmsm.html)

### 4.3 保留两个可切换的被控对象

建议让同一个控制器连接两个 Plant 变体：

- **快速模型**：平均逆变器加电机模型，用于 PI 调参、启动过程、速度和负载工况、参数扫描。
- **开关模型**：原生三相桥加电机，用于 PWM、死区、采样窗口、电流纹波和电压饱和检查。

先保证两者在相同条件下的平均电流、转矩和速度响应相符，再用开关模型研究高频细节。原生 Converter 的 PWM 等效模式与理想平均值模型不是同一个概念，应分别明确所选保真度。

官方有可切换平均/Simscape 开关模型的 FOC 示例，其部署目标是 TI C2000。我们参考其 Plant 组织方式；STM32 的外设与部署部分参考 ST 专用例程。[R2026a 开关动态建模示例](https://www.mathworks.com/help/releases/R2026a/mcb/gs/modeling-switching-dynamics-in-inverter-using-simscape-electrical.html)

## 5. 要贴近固件，优先对齐这六件事

### 5.1 控制器的离散算法

按固件还原 PI 的逐拍计算：积分使用当前误差还是上一拍误差；Ki 是否已经乘采样周期；先更新积分还是先输出；抗饱和采用什么方式；停机和故障时状态如何复位。

速度环的输出究竟是 `iq_ref`、转矩还是标幺值，需要固定一种接口定义。前次检查发现仓库的速度 PI 设计对象与 `Te_ref` 命名存在单位需要核对的地方，不能直接继承参数。

电流环、速度环和位置环分别设置真实执行周期，慢任务按实际计数分频或调度方式运行。**环路带宽是 50 Hz，不表示任务应以 50 Hz 运行。** 仓库速度 PI 封装中的 `1/fwb` 与内部 `dt` 不一致，也需重做。

### 5.2 PWM 定时器与命令生效时刻

从 `.ioc` 和固件读取定时器实例、时钟树、PSC、ARR、中心/边沿对齐、RCR、预装载、更新事件、输出极性、死区及刹车输入。

仿真先产生占空比命令，再按固件的舍入、限幅和映射得到整数 CCR；写入影子寄存器后，在实际更新事件才切换有效值。禁止把“计算完新占空比”自动等同于“逆变器立即生效”。

PWM 周期要由实际定时器时钟和配置推导，不能直接将 MCU 最高 170 MHz 当作全部外设时钟。G474 有高级定时器和 HRTIM；使用哪一个由实际固件决定。

### 5.3 ADC 与电流采样窗口

建立：采样电阻、运放增益与偏置、模拟 RC、ADC 采样保持、转换延迟、量化与饱和、零点校准、数字滤波和采样有效性。

输入链路最终最好输出固件实际读取的 ADC 数字码，让固件自己的换算函数把它转成电流/电压。ADC 位数、过采样和右移方式都取实际配置。

必须按一电阻、两电阻、三电阻或相内传感器的实际拓扑建模。低边采样不一定在任意 PWM 状态都可测；单电阻还需要矢量窗口、电流重构，可能需要移相或最小脉宽处理。不能默认三个理想相电流传感器等同于实际采样电路。

### 5.4 ADC—ISR—PWM 调度

模型中的事件链为：

```text
定时器触发 t_s
  → ADC 采样与转换
  → 转换完成 t_eoc
  → 中断响应与控制计算
  → 写入 CCR 影子寄存器
  → 指定更新事件 t_latch
  → 门极驱动和功率器件响应
```

至少参数化 `T_adc`、`T_irq`、`T_calc`、更新规则和门极延迟。实际计算完成必须赶上目标锁存事件；赶不上时，模型也应表现为继续使用旧命令。

例如 PWM 为 20 kHz 时周期是 50 μs，但这并不代表 FOC 计算有完整 50 μs 可用。预算取决于采样位置、转换完成时间和下一次锁存点。当前电机/驱动板未知，20 kHz 仅可沿用为框架占位值。

MathWorks 的 G474RE 参考例程有 TIM1 触发 ADC 注入转换、转换完成后调度算法的结构，可作为阅读入口；具体触发点和采样窗口仍需匹配实际采样电路。[G474RE 无感例程](https://www.mathworks.com/help/releases/R2026a/stm32b/ug/senorless-stm-example.html)

单次/双次更新、提前采样和不同采样频率的影响，可参考 [R2026a 采样与 PWM 架构示例](https://www.mathworks.com/help/releases/R2026a/mcb/gs/motor-control-using-different-current-sampling-pwm-frequencies.html)。这个示例的板级部署目标是 TI，时序分析方法可以借鉴。

延迟应来自配置、数据手册或实测；不能仅为绕开代数环任意插入一拍。桌面物理仿真可以使用变步长求解器，同时让控制器保持离散和事件调度；生成控制代码时再落实固定执行周期。控制采样周期不等于电气求解步长。选择电气步长后，应缩小步长比较结果，确认没有漏掉所研究的死区和采样窗口。

### 5.5 位置与速度反馈

根据最终硬件选择编码器、霍尔、SPI 磁编码器或无感估算器变体，复现计数分辨率、零角标定、方向、通信/计算延迟、速度滤波和角度补偿。

无感方案还需复现对齐、开环启动、观测器收敛和闭环切换；只用电机真值角度不能验证这些过程。真实角度仍可保留为误差评估信号。

### 5.6 电压电流约束与状态机

按固件实现矢量电压限幅、母线电压归一化、占空比上下限、最小脉宽、死区、过流/欠压处理，以及校准—对齐—运行—停机—故障状态。

仓库中的各轴独立电压限幅还不能自动保证最终矢量与 PWM 命令始终可实现。内嵌 SVPWM 的顺序归一化错误应在新控制实现中修正，并记录与原模型的差异。

## 6. 固件接入建议

### 已有手写 C 固件时

优先提取并复用已有的控制核心，例如 PI、坐标变换、观测器、限幅和 SVPWM。用 C Caller 或适当封装在桌面调用同一份 C 算法，保留状态初始化与复位接口。[R2026a C Caller 文档](https://www.mathworks.com/help/releases/R2026a/simulink/slref/ccaller.html)

HAL/LL、寄存器读写、中断入口和通信驱动应与控制数学函数分离，主机仿真使用输入输出适配层。直接在桌面执行整份含 MCU 寄存器操作的固件通常不成立。涉及 CORDIC/FMAC 或其他芯片专用操作时，需要主机等价实现，并通过同一输入序列验证误差。

保留一个可观察的模型算法版本与 C 版本，输入完全相同的电流、角度、电压和指令序列，逐拍比较 `id/iq`、积分状态、`vd/vq`、占空比/CCR 与运行状态。

### 后续希望由模型生成控制代码时

将 Controller 做成独立可生成代码的子系统/引用模型，Plant 和测量仿真留在主机。通过 STM32 Microcontroller Blockset 接 ADC、PWM 和中断等外设，或将生成的控制函数集成进现有工程。

整个电机、电路和 MCU 不一起生成到 G474 上执行。生成代码与保留手写固件两条路线可以共用相同的仿真 Plant 和接口定义，具体选择等固件到位后确定。

## 7. 开发阶段与验收产物

| 阶段 | 开发内容 | 这一阶段如何判断完成 |
| --- | --- | --- |
| 1. 新版基线 | R2026a 原生电气 Plant，统一参数与单位，整理控制接口；记录原模型问题 | 模型能编译运行；正转方向、转矩符号、坐标变换与参数定义检查通过 |
| 2. 控制闭环 | 离散电流环、速度环、限幅、启停状态；先使用理想反馈验证算法 | 电流给定、速度给定、负载扰动下得到可解释响应；记录电流峰值、超调、稳态误差 |
| 3. 板级测量和时序 | 实际采样拓扑、滤波、ADC、PWM、死区、锁存、任务周期 | 有事件时序记录；改变采样点或延迟时可观察影响；检查采样有效窗口和更新截止时间 |
| 4. 固件算法一致性 | 接入真实 C 控制核心，统一数据类型、状态和复位 | 相同输入序列逐拍比较通过；误差阈值根据实际数值类型制定 |
| 5. G474 验证 | 按选定路线做 PIL 或板端控制函数验证、执行时间测量 | 对比目标端数值结果，记录实际任务负载下的最大观测执行时间及余量 |
| 6. 实测校准 | 用真实母线、电流、转速、占空比和事件时间更新参数 | 在未参与调参的另一组工况中，也能解释主要动态与误差 |

PIL 可验证目标处理器上的代码数值和执行表现，不能独自证明真实 ADC/PWM 整条链路正确。需要进一步使用板上 GPIO/逻辑分析仪/定时计数等核对触发和更新时间；最大观测执行时间也不是形式化最坏执行时间证明。[R2026a STM32 PIL 示例](https://www.mathworks.com/help/releases/R2026a/stm32b/ug/STM32F4xx-PIL-example.html)

HIL 可以作为之后的扩展：真实 MCU 控制实时运行的虚拟电机和功率级，但需要额外实时仿真与 I/O 条件，当前先不将其设为第一版前置条件。

## 8. 参数和工程组织草案

建议建立统一参数结构，注明每个值的来源、单位和状态：

| 参数组 | 内容 | 当前状态 |
| --- | --- | --- |
| `motor` | 电机类型、接法、Rs、Ld/Lq、磁链、极对数、J、摩擦、温度 | 待实际电机数据；仓库值仅用于模型结构演示 |
| `inverter` | Vdc、母线电容/ESR、开关类型、Ron/压降、驱动延迟 | 待功率板资料 |
| `sense` | 拓扑、采样电阻、增益/偏置、RC、ADC 设置、位置传感器 | 待原理图与固件 |
| `timing` | 定时器时钟、PWM、ADC 触发、EOC、计算耗时、更新事件 | 待 `.ioc`、中断源码与实测 |
| `control` | PI、限幅、滤波、观测器、启动状态、数据类型 | 待固件；先定义接口和占位算法 |
| `target` | STM32G474RET6、编译器、优化、浮点 ABI、库版本 | MCU 已知，其余待工程 |

拟议的新开发目录如下；这是规划，不表示这些模型已经创建：

```text
modern/
  params/           # 统一参数、单位约定、板级配置
  controller/       # 模型控制器及 C 控制核心适配
  plant/            # 快速模型与原生开关模型
  io_model/         # 采样、位置反馈、PWM、事件调度
  harness/          # 闭环场景、算法对比、目标端验证
  validation/       # 输入序列、波形、指标和对比结果
```

电机和板级资料到位前，最适合先完成阶段 1 的结构设计、接口、单位和快速模型，再推进阶段 2；阶段 3 的真实参数、阶段 4 的 C 接入必须等待对应资料。

## 9. 后续资料按什么顺序补充

后续陆续提供即可，当前不需要把所有信息一次整理齐：

1. **固件工程与 `.ioc`**：先确定实际控制周期、PWM/ADC 外设、触发规则和已有算法。
2. **功率板原理图或采样/驱动部分参数**：确定电流反馈拓扑、增益、滤波、死区和保护链。
3. **电机型号、接法、额定参数与已有测量数据**：更新 Plant，统一峰值/RMS 和相/线参数口径。
4. **位置反馈信息**：编码器、霍尔、磁编码器或无感控制，以及对应零角和方向定义。
5. **一组实测波形或日志**：母线、电流、速度、占空比和触发时序，用于校准与独立验证。
