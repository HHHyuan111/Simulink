目前已确认 MATLAB R2026a 和 MCU 型号。电机、功率板、电流采样拓扑、位置反馈和固件工程尚未提供，因此 24 V、20 kHz、Rs=0.14 Ω 等仍是示例值。开发计划不把它们当成实际硬件参数。资料核对日期为 2026 年 10 月 11 日，MathWorks 页面优先使用 R2026a 归档版本。

## 先定义仿真要回答的问题

第一阶段回答控制算法是否按约定工作：变换和转矩单位正确吗，PI 饱和后能恢复吗，SVPWM 给出的电压符合要求吗。第二阶段回答板级现象：采样位置不合适时电流为何跳变，母线下降时为何跟踪变差，角度误差为何产生 d 轴电流。第三阶段回答固件一致性：同一组 ADC 和角度输入，仿真与板上代码是否算出一致的电压和 CCR，以及结果是否赶上本次 PWM 更新。

“接近实际”应落实到可比较的记录，而不是不断增加复杂模块。对每个目标记录输入工况、参数版本、采样时刻和允许误差；不能只靠转速曲线相似来验收。

| 层次 | 模型用途 | 主要比较对象 |
| --- | --- | --- |
| 算法 | 验证数学、符号、限幅和离散状态 | 逐步计算结果与解析关系 |
| 板级行为 | 验证采样、调制、测量误差和功率器件影响 | ADC 波形、门极、相电流、母线与角度 |
| 固件 | 验证真实 C 运算、更新顺序和状态机 | 同一输入的 PI 状态、dq 电压、占空比和故障状态 |
| 实物闭环 | 校准模型并确认适用范围 | 同一工况下的实测电流、速度及动态指标 |

## 资料依据和采用边界

STM32G474RE 提供 Cortex M4、单精度 FPU，以及 CORDIC 等计算资源，最高内核频率为 170 MHz。这里的上限不等于你的工程已经运行在该频率，封装可用引脚也要以 RET6 对应资料和原理图确认。[ST 产品页](https://www.st.com/en/microcontrollers-microprocessors/stm32g474re.html)及[DS12288 数据手册](https://www.st.com/resource/en/datasheet/stm32g474re.pdf)是器件能力与引脚核对入口。

MathWorks R2026a 已提供 Nucleo G474RE 的 PMSM FOC 示例，可参考其中 PWM 触发 ADC、转换完成触发控制计算的组织方式。示例使用指定电机和扩展板，其引脚、传感方式及参数不能直接当作你的板子配置。[R2026a STM32 PMSM FOC 示例](https://www.mathworks.com/help/releases/R2026a/stm32b/ug/senorless-stm-example.html)

官方资料说明了不同电流采样频率与 PWM 更新方式，以及单次、双次更新等方案。它们是理解延迟的参考；该采样架构页面的部署示例面向其他处理器，STM32 的寄存器及事件选择仍须按固件确认。[采样和 PWM 频率架构](https://www.mathworks.com/help/releases/R2026a/mcb/gs/motor-control-using-different-current-sampling-pwm-frequencies.html)

ST 的 ADC 应用笔记讨论参考电压、输入源阻抗、采样时间、校准等误差来源。仿真中的 ADC 应从实际电路和配置推导，不能只在电流上随便叠加一条白噪声。[AN2834 ADC 精度](https://www.st.com/resource/en/application_note/an2834-how-to-optimize-the-adc-accuracy-in-the-stm32-mcus-stmicroelectronics.pdf)

以下分阶段安排属于针对当前模型的工程建议。引用资料支持器件能力、软件接口和采样原理；优先级、实施步骤及验收方法由当前模型的问题和你的开发目标推导。

## 阶段 0 固定可追溯的学习基线

先保留当前 SLX、参数源码、329 块清单、布局验证记录和默认日志。给工况、参数及工具版本编号，保留这次确认的图和逐模块解读。今后算法变化独立记录，不再把外观整理与控制变化混在一次修改里。

在九个色域之间列出信号约定：rpm 与 rad/s、机械角与电角、相电压与线电压、峰值与 RMS、电流方向、六路 SW 排列、Tcm 与 CCR 的关系。电机真值和传感器输出使用明确的不同名称。参数区写清“示例”“实测”“数据手册”“辨识”四种来源及日期。

交付物是基线快照、参数表和工况脚本。验收条件是能在 R2026a 用固定参数重复得到相同结果，并能从每个日志追溯其来源。现有布局前后逐点一致的验证可以作为起点；它不替代后续算法正确性验证。

## 阶段 1 修清当前算法和单位

### 速度环和电流环

先决定速度 PI 输出的物理量。建议结合真实固件选择：若固件直接输出 iq_ref，就按 A 统一增益和限幅；若输出转矩，就按 N·m 设计，并只做一次转矩到电流换算。同步修正当前分母中的 Ld·id 与电机转矩方程不一致的问题，不能只删除一个 Divide 后照搬原 PI 数值。

让速度环采样参数真正控制内部离散块，带宽和执行频率分别命名。速度环是否采用较慢频率，以固件调度和设计带宽为依据。例如 20 kHz 电流环配合 1 kHz 速度环只是候选架构，尚不是你的板子配置。多速率边界规定何时读入、何时更新和保持。

让 d 轴 PI 绑定 d 轴参数。核对 q 轴完整前馈，明确非零 id 时怎样处理耦合；在前馈之后对最终电压矢量限制，并把可实现电压与未限幅电压的差反馈给抗饱和。离散积分顺序、复位和积分状态限幅应写成可逐步核对的方程。

### 调制函数

修正 SVPWM 过调制中先修改一个有效矢量时间、再用修改后的和计算另一个时间的问题。归一化前保存共同分母，同时处理 Vdc 无效、零矢量、扇区边界和最小脉宽。选定限幅策略后，PI 抗饱和要使用对应的实际可实现电压。

规定 Tcm 时间阈值怎样转换成硬件 CCR，核对 PWM 模式、比较极性、中心对齐计数方向和相序；当前载波比较的理想关系不能直接当成所有定时器模式的 CCR 公式。

交付物是独立算法修复记录和测试向量。验收包括变换往返、解析转矩、单步 PI、饱和恢复、各扇区平均电压、零矢量、低母线及过调制。算法改变后不应再要求与旧日志逐点相同，而应要求符合预先定义的物理关系和新行为。

## 阶段 3 按真实事件重建采样和 PWM 时序

当前 ZOH 和 Rate Transition 不能代表完整 MCU 时序。需要在模型中表达以下事件：电流在采样窗口被捕获、ADC 转换完成、控制中断开始、控制计算完成、CCR 写入预装载寄存器、更新事件使其生效、功率桥产生对应边沿。采样保持的物理时刻与 ADC 数据可用时刻应分别表示。

从固件提取时间线并实测核对：ADC 触发相位、转换和中断延迟、计算时间、CCR 更新期限。中心对齐 PWM 并不自动意味着固定一个周期延迟；是否在计数峰值或谷值更新、每周期执行几次，要结合预装载、重复计数器和触发配置。

MathWorks G474RE 示例选择 TIM1 更新事件触发注入组 ADC，RCR=1，使其每个 PWM 周期产生一次对应更新；ADC 完成再触发计算。这是可参考的一种配置，最终以你的工程为准。[R2026a G474RE 示例时序](https://www.mathworks.com/help/releases/R2026a/stm32b/ug/senorless-stm-example.html)

在现有 SVPWM 与采样区域附近增加事件及保持行为，先用理想电机测试。画出一个周期内的 ADC 采样点、计算窗口与 CCR 生效点，再把它和逻辑分析仪或示波器记录对齐。定时器、ADC、比较器及故障输入的具体配置按[RM0440 参考手册](https://www.st.com/resource/en/reference_manual/rm0440-stm32g4-series-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)对应章节核对，本文不代替完整寄存器审查。

交付物是时序表和单周期示意记录。验收条件是能解释一次给定或测量变化在哪次 PWM 生效；模拟超时后能出现真实固件对应的旧占空比保持或故障行为，而不是默认瞬时完成计算。

## 阶段 4 接入电流和位置测量链

### 电流和母线测量

把电机真实相电流转换为采样电路电压，依次加入分流与增益、零点偏置、RC 动态、供电及放大器范围、ADC 量化和饱和，再使用同一固件标定系数还原电流。噪声幅度、频谱及相关性由实测决定；先分别施加偏置和增益误差，观察它们怎样进入 id、iq 和转矩。

单分流、双分流和三分流需要不同的相电流可观测窗口及重构规则。必须结合开关状态判断样本是否有效；不能无论占空比多高都直接读取理想三相电流。高调制度、扇区边界和很窄脉冲时，记录无效样本标志及固件补偿方式。ST 的单分流资料可用于理解最小采样窗口和移相处理，但是否需要这些算法取决于实际拓扑。[ST 单分流移相](https://wiki.st.com/stm32mcu/wiki/STM32MotorControl:Single_Shunt_Phase_Shift)

母线采样同样考虑分压、滤波、量化、采样频率和延迟。电压前馈应读固件实际可获得的母线值，功率桥则使用真实母线状态。

### 角度和速度

按照实际传感方式实现：编码器要处理计数、机械零位、极对数和差分测速；霍尔要处理扇区及插值；SPI 磁编码器要处理读数延迟和角度环绕；无感方案要接入对应估算器及其启动切换。当前 RE=1024 没有进入主反馈，不能通过修改这个数字完成传感器适配。

给反馈单独施加角度偏置、方向错误、丢帧和延迟，核对 id 偏移、转矩脉动与失步趋势。保留电机真值供诊断，但断开控制器读取真值的旁路。采用哪一种反馈等待你的硬件信息，不预先强制无感控制。

交付物是测量参数表、原码至物理量的换算测试和有效性日志。验收包括静止零电流校准、已知电流增益验证、角度一圈和反转检查、ADC 饱和及无效窗口处理，以及控制回路只读取模拟测量值。

## 阶段 5 逐项增加功率级和电机的非理想因素

先分出两种仿真用途：平均电压表示适合长时间速度和参数扫描；开关表示适合短时间检查采样窗口、死区和电流纹波。它们共用控制参数和接口，明确各自能回答的问题，不为每次长时间运行都求解所有高频细节。

死区应包含同一桥臂上下管均关断的状态，以及电流方向决定的续流通道。当前桥公式依赖理想互补开关，只给 NOT 支路增加延迟会产生错误的关断状态电压。随后根据需要加入 MOSFET 导通电阻、二极管压降、驱动延迟、最小脉宽、母线电容及 ESR、供电阻抗和再生吸收限制。

电机先标定 Rs、Ld、Lq、磁链、惯量和负载。再按实测误差决定是否增加温度影响、饱和、干摩擦、齿槽转矩或磁链谐波。不能用大量未知参数拟合一条速度曲线，也不要用 PI 增益弥补错误的电机常数。

如需转向器件级电气网络，可评估 Simscape Electrical 的[PMSM](https://www.mathworks.com/help/releases/R2026a/sps/ref/pmsm.html)和[三相变换器](https://www.mathworks.com/help/releases/R2026a/sps/ref/converterthreephase.html)；这是一条可选扩展路线，当前普通 Simulink 电机方程仍可承担算法与时序研究。更换电机表示时先核对 dq 变换约定和参数单位。

交付物是每个新增因素的参数来源、单独影响曲线和运行耗时。验收采用步长收敛检查，分别比较平均转矩、控制采样点电流和高频纹波；不同指标不能共用一个未经说明的收敛结论。

## 阶段 6 让仿真运行真实固件核心

把固件中的 Clarke、Park、PI、限幅、SVPWM 和状态机整理为可在电脑编译的 C 接口，外设寄存器与 HAL 读写保留在适配层。仿真向核心提供模拟 ADC 结果、角度、母线、给定和故障输入，核心返回电压、占空比或 CCR 与状态。这样可以继续在原模型旁对照小模块，并最终使用同一份核心代码。

R2026a 的 C Caller 可以在 Simulink 中调用外部 C 函数。桌面仿真需要兼容的 C 编译器及适当的接口；单纯调用 C 不等于已完成 STM32 自动部署或正式 SIL 验证。[C Caller 官方文档](https://www.mathworks.com/help/releases/R2026a/simulink/slref/ccaller.html)

明确初始化、复位、静态状态、采样周期、运算顺序和数据类型。若板上用 float32，就对齐 single 的运算及常量；若使用定点或 CORDIC，则核对缩放、舍入、饱和与三角函数误差。不能仅因为 G474 有 CORDIC，就假设固件已经使用它。

先用固定输入向量逐步比较 Simulink 和 C 的误差、PI 积分状态、最终电压和 CCR，再接入闭环。完全相同的整数实现可按位核对；跨数学库的浮点实现采用预先约定的容差，同时检查接近扇区或限幅边界的分支一致性。

交付物是可独立构建的固件核心、接口说明和差分报告。验收重点是同一输入历史得到一致的输出与状态，含复位、饱和和故障恢复；只比较最终稳态速度是不够的。

## 阶段 7 按需要增加目标处理器验证

桌面 C 对齐后，可选择 PIL，把核心放到目标 MCU 执行并与桌面结果比较。PIL 有助于检查目标编译器和处理器数值行为；通信往返时间不能直接当成真实控制中断的执行时间。MathWorks 提供 STM32 的[PIL 工作流示例](https://www.mathworks.com/help/releases/R2026a/stm32b/ug/STM32F4xx-PIL-example.html)，具体 G474 工程和工具依赖还需按当前产品配置验证。

板上使用 DWT 周期计数或 GPIO 脉冲测量控制中断起止，记录最坏执行时间、抢占、抖动及 PWM 更新期限。只有算得完、写得及时，仿真的时序结论才能用于固件。HIL 需要额外的实时仿真设备和接口，等确有故障注入或闭环实时验证需求再决定。

若采用 MathWorks 的 STM32 自动部署，R2026a 官方表列出的工具组合为 CubeMX 6.12.0、CubeProgrammer 2.17.0、GNU 13.2.1、Arm Clang 6.22 和 CubeCLT 1.17.0。它们是该工作流的兼容性依据，不能据此强制升级或降级你已有的手写固件工程。[R2026a 工具兼容表](https://www.mathworks.com/help/releases/R2026a/stm32b/gs/supported-stm32-boards.html)

## 阶段 8 用实物数据校准和验收

先在限流、低母线和受控负载条件下确认相序、传感器方向、零位、硬件关断和启动过程，再采集与仿真相同的工况。保护阈值和操作范围由实际板子、电机及实验条件确定，不使用示例模型的电流限幅代替硬件额定值。

日志按时间事件对齐，统一量纲、采样频率、滤波和峰值口径。分别比较静态零偏、稳态电流、母线变化、加速时间、负载阶跃、转速超调和关断响应。先用独立数据辨识电机及测量参数，再用未参与拟合的工况验证，避免只把一个工况调得相似。

阈值按测量精度和用途约定。例如相电流误差可分别报告偏置、RMS 和峰值，转速可报告稳态误差、超调和整定时间；不要未经讨论就把某个百分比当作通用合格线。每次结果应给出模型适用范围，例如“中低调制度且电流采样窗口有效”，而不是声称覆盖全部运行状态。

| --- | --- | --- |
| 变换和相序 | abc 与 dq 往返、0 和 π/2 角度 | 符号与解析关系一致，零序处理明确 |
| PI 单步及复位 | 比例项、积分状态、输出与清零 | 与选定离散方程逐步一致 |
| 启动和速度阶跃 | iq_ref、iq、转速、饱和状态 | 不超越已定电流范围，动态符合目标 |

## 工具选择和近期顺序

当前已安装的 MATLAB 和 Simulink 足以完成学习、算法修复、普通电机方程、事件时序和基本误差模型。桌面 C 接入还需编译器。Motor Control Blockset、Simscape Electrical、Simulink Coder、Embedded Coder 和 STM32 Microcontroller Blockset 是否需要安装，取决于所选模块及是否采用自动生成和部署；先确认用途与许可，再增加依赖。

建议近期按以下顺序推进：先读懂速度环、电流环和调制，把阶段 1 的几处问题逐项修复并验证；收到固件与原理图后完成阶段 2 和 3；随后对齐电流、角度和母线测量；最后接入同一 C 核心并用板上数据校准。高保真器件模型和 PIL 可以在已知误差需要它们时追加。

每次只改变一个可解释的因素，保存修改原因、参数来源、工况和结果。这样原模型始终可以回看，也能明确判断哪一项改动使仿真更接近开发板。

## 后续第一次硬件对接需要什么

你提供电机型号或参数表、功率板原理图或型号、位置传感器信息和固件工程目录后，优先提取定时器与 ADC 配置，再审查电流换算和 PI 核心。第一次对接的结果应是一张实际参数表、一张 PWM 与 ADC 时间线，以及模型色域到固件函数的对应表，而不是立即替换全部模块。
