## 判断

上一轮主要调整了坐标、字体和颜色，仿真行为保持一致，但阅读结构仍不足以作为长期使用的界面。问题是功能层次和信号方向没有在图面上表达清楚，不能只继续加深颜色、挪动方块。

当前有 164 个顶层块，其中 25 个 Goto、37 个 From、17 个 Scope，另有 1 个 XY Graph。上排三个区域与下排三个区域的列边界不一致：例如中列上排从 x=900 开始，下排从 x=850 开始。正变换和逆变换挤在同一区域，功率级放在控制器之前，实际闭环又依赖跨区域标签，阅读顺序出现跳转。多个替换子系统为空白矩形、外部名称很长；观测区混有重复曲线、辅助 Chirp 参考和验证记录，层次不明确。

现有布局回归报告证明的是：默认 1 秒运行中，12 路已记录信号与整理前逐点一致。它不能证明原控制器单位、采样周期、过调制与硬件模型都正确。

## 目标结构

在同一个现有 SLX 内整理。保留并按功能封装现有计算块，不另外建立仿真主模型。封装会改变层级和块路径，需要单独做等价核对；第一阶段保留原公式、参数、状态、采样周期与控制执行方式。

顶层主通道：

```text
给定 → 速度环 → 电流环 → 逆Park → SVPWM → 逆变器 → PMSM
          ↑        ↑         ↑                         │
          n     id/iq/ωe      θe                        │
          └────────┴─────────┴────── 采样反馈 ←─────────┘

数据观测：读取给定、反馈、电压、门极与负载；不参与控制反馈。
```

`给定` 提供真实的主速度给定和 d 轴电流给定；母线电压进入逆变器并供调制计算使用，负载转矩进入电机。`速度环` 第一阶段包含原速度 PI 和原转矩/电流换算，保持 iq_ref 接口；`电流环` 包含 d/q PI 与原前馈支路；`采样反馈` 包含反馈向量拆分、采样、电机械量换算、Clarke/Park。详细 d/q 控制计算在电流环内部横向展开，上 d、下 q。

顶层约 9 个功能入口，内部原计算块继续可见。可以保留额外参数入口，顶层数量不作为强制指标。数据观测和辅助测试不占据主链走线空间。

## 排版与走线

1. 主链左到右；反馈在独立下方通道返回，母线和负载从对应对象旁进入。逆 Park 与 Park 分别放在电压指令路径和电流反馈路径，避免混成同一个大色块。
2. 顶层入口块宽高统一，按 10 px 网格布置；相邻块间距按最长端口名称预留，控制块中线一致。区域起止边界对齐，正文留白一致。字大小按实际打开的编辑器窗口检查，不以导出全图的缩小效果代替。
3. d/q 两行 PI、误差计算、前馈、求和分别对齐。三相 PWM 的 A/B/C 三行完全对齐，互补门极顺序明示为 `[AH AL BH BL CH CL]`。
4. 主链使用显式 Inport/Outport 和直角连线，端口就近标注。反馈按速度、电流、角度分路，线不穿过模块或文字，不用斜线，不让 Scope 分支绕过控制器。
5. 不为了整齐强行插入 Unit Delay、Rate Transition 或更改执行频率。第一阶段新增封装采用普通虚拟子系统，维持原有执行语义。
6. Goto/From 逐项建立生产者/消费者表。当前 `Iabc`、`Uabc`、`Umod` 等含局部标签，不能直接拖入不同子系统。跨功能接口改成显式端口，观测标签限定在清楚的范围，避免用更多全局标签掩盖连接问题。

局部标签只在同一子系统可见，跨非虚拟边界也有约束，参见 [MathWorks Goto 文档](https://www.mathworks.com/help/simulink/slref/goto.html)。

## 数据观测

顶层只留一个 `数据观测` 入口，内部按 `速度`、`电流`、`电压`、`PWM` 排列。

默认展示真实主给定与反馈：n_ref/n、id_ref/id、iq_ref/iq，以及母线、转矩和 PWM 诊断。归一化误差只与相应的真实给定比较。原 Chirp 与相应误差对照移入辅助测试，第一阶段保留，不删除，也不把它们显示成主控制给定。

重复 Scope 可先移入内部次级观测，后续再根据实际使用决定是否合并。验证数据记录继续保留，记录名称保持可追溯。

## 控制逻辑审查顺序

这些修改会改变仿真行为，应放在布局等价核对之后逐项进行。

| 优先级 | 当前证据 | 修复方向 | 专项核对 |
|---|---|---|---|
| P0 | 速度 PI 增益公式含转矩常数，输出又按 Te_ref 除以转矩常数；限幅按转矩定义 | 统一输出为电流 A 或转矩 N·m，再同步核对增益、限幅、换算。面向电流控制固件，优先评估直接输出 iq_ref | 启动、负载突变、反转、饱和恢复 |
| P0 | SVPWM 先修改 t1，再以新 t1+t2 计算 t2 | 使用同一个原始总和缩放，或明确在调制前限制线性区输入；保留原 SVPWM 主体便于学习 | 六扇区、边界、零输入、超限输入、低母线 |
| P0 | PI 输出分别限幅，前馈在限幅后加入 | 对最终 dq 电压进行与母线能力一致的矢量限幅，抗饱和跟踪实际施加电压 | 大阶跃、低母线、无法达到的转速与恢复 |
| P1 | d 轴 PI 使用 q 轴参数；q 轴前馈的 Ld*id 支路未使用 | d/q 参数分开、补全前馈，核查凸极转矩公式。先明确支持 SPMSM 还是更一般 PMSM | Ld≠Lq、id 非零 |
| P1 | 速度 PI 封装 SampleTime=20 ms，内部实际使用 50 μs | 先修正显示与实际不一致；再按固件调度设置速度环和电流环执行周期，不能把设计带宽当采样率 | 编译采样时间、执行周期与阶跃响应 |
| P1 | 原辅助比较用 Chirp 标签，实际主给定来自常数 | 数据观测默认接真实主给定，辅助测试单独管理 | 真给定/曲线来源一致，控制反馈不变 |
| P2 | 理想逆变器与连续 dq 电机，未接入实际硬件数据 | 实际电机参数、采样比例/偏置、ADC 触发、PWM 更新延迟、编码器/Hall 量化，再按需要增加死区和续流模型 | 与 STM32G474RET6 固件信号逐项对照 |

电流控制、dq 电压与母线相关的限制可参考 [MathWorks FOC 电流控制文档](https://www.mathworks.com/help/mcb/ref/fieldorientedcurrentcontroller.html)。这是原理参考，本方案不要求安装或替换成 Motor Control Blockset。

## 实施与验收

1. 保存当前备份和模块/信号映射。先改短名称、配色、对齐、图标文字与走线，再封装已有细节。每次封装一组，更新所有依赖旧路径的初始化、验证和布局脚本。
2. 对照已有计算块和 MATLAB Function 源码核对公式、参数、状态、端口、维度、单位、采样周期与实际数据来源。名称和路径允许按映射变化，不能把路径变化当功能变化，也不能仅核对块总数。
3. 先在默认工况比对现有 12 路记录，再在零指令、反转、负载阶跃等共同输入下核对。布局和等价封装应保持波形一致；如果出现差异，定位标签、端口、执行或记录时序的原因后再继续。
4. 用真实 Simulink 编辑器逐层检查：主链顺序连续，区域边界对齐，主要名称短且可读，线条不穿块、不压字，d/q 与三相行列对齐，主界面不铺开全部 Scope。
5. 布局通过后，按上表逐项修控制逻辑。每项独立记录触发工况、前后波形和专项验证，避免一次改多个算法导致结果无法解释。

第一阶段验收结果应称为“清楚、可运行、行为一致的学习模型”。只有真实硬件参数、固件调度和算法专项验证接入后，再判断它是否具备板卡开发基线资格。
